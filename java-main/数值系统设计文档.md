# 《凡人修仙传》数值系统设计文档

> 项目：fanren-login（Vue 3 + Spring Boot + MySQL）
> 版本：v1.0　　|　　更新：2026-10-30
> 用途：为角色「生命、寿元、攻击、防御、速度」五维属性提供一套可计算、可成长的数值体系。

---

## 一、设计目标

1. **可成长**：角色每提升一个小境界，五维属性按规则增长。
2. **可叠加**：功法、法宝、体质、灵根均能为属性提供加成，最终属性 = 各来源之和。
3. **可区分**：不同品阶（天/地/玄/黄）的加成差异明显，高品阶显著强于低品阶。
4. **可落地**：所有规则都能映射为数据库字段 + Java 计算逻辑 + 前端展示。

## 二、境界体系

### 2.1 九大境界（由低到高）

| 序号 | 境界 | 阶段 | 寿元上限（年） | 备注 |
|:---:|:---|:---|:---:|:---|
| 1 | 练气期 | 炼精化气 | 100 | 入门，凡人之躯 |
| 2 | 筑基期 | 筑基 | 200 | 铸就道基 |
| 3 | 金丹期 | 金丹 | 500 | 结成金丹 |
| 4 | 元婴期 | 元婴 | 1000 | 元婴出窍 |
| 5 | 化神期 | 化神 | 2000 | 化神飞升 |
| 6 | 炼虚期 | 炼虚 | 4000 | 炼虚合道 |
| 7 | 合体期 | 合体 | 8000 | 身神合一 |
| 8 | 大乘期 | 大乘 | 15000 | 大乘圆满 |
| 9 | 渡劫期 | 渡劫 | 30000 | 渡劫飞升 |

### 2.2 小境界（每大境界 9 层）

每个大境界内部再分 **初期 / 中期 / 后期** 三个阶段，每阶段 3 层：

```
初期：一层、二层、三层
中期：四层、五层、六层
后期：七层、八层、九层
```

示例：
- `练气期 初期 一层`（修为总第 1 层）
- `练气期 后期 九层`（修为总第 9 层）
- `筑基期 初期 一层`（修为总第 10 层）

**修为总层数** = (境界序号 - 1) × 9 + 小境界层数，从 1 到 81。

### 2.3 境界存储编码

为便于计算与排序，用「整数」存储修为总层数，用「字符串」做可读展示：

| 字段 | 类型 | 说明 |
|:---|:---|:---|
| `realm` | varchar | 可读境界名，如 `练气期` |
| `realm_level` | int | 境界序号 1–9 |
| `sub_level` | int | 小境界层数 1–9 |
| `stage` | varchar | 阶段：初期/中期/后期 |
| `total_level` | int | 修为总层数 1–81（冗余，便于快速比较） |

## 四、境界成长公式

每提升 **一个小境界**，五维属性按「境界成长系数」累加。成长系数随境界序号非线性放大（后期提升幅度大于前期）。

### 4.1 单层成长量公式

```
单层生命成长 = 基础生命成长(50) × 境界序号
单层寿元成长 = 该境界寿元上限 / 9
单层攻击成长 = 基础攻击成长(8) × 境界序号
单层防御成长 = 基础防御成长(8) × 境界序号
单层速度成长 = 基础速度成长(5) × 境界序号
```

> 境界序号越大，每层提升越多，体现高境界差距拉开。

### 4.2 属性总量公式

```
生命 = 100 + Σ(每层生命成长) + 体质生命加成 + 功法生命加成 + 法宝生命加成
攻击 = 10 + Σ(每层攻击成长) + 灵根攻击加成 + 体质攻击加成 + 功法攻击加成 + 法宝攻击加成
防御 = 10 + Σ(每层防御成长) + 体质防御加成 + 功法防御加成 + 法宝防御加成
速度 = 10 + Σ(每层速度成长) + 灵根速度加成 + 体质速度加成 + 功法速度加成 + 法宝速度加成
寿元 = 境界寿元上限 + 体质寿元加成 + 功法寿元加成 + 法宝寿元加成
```

## 五、品阶加成（天地玄黄）

功法与法宝均有品阶。不同品阶提供不同的属性加成倍率与基础加成。

| 品阶 | 倍率 | 说明 |
|:---:|:---:|:---|
| 黄 | ×1.0 | 最基础，入门级 |
| 玄 | ×2.0 | 中品，常见 |
| 地 | ×4.0 | 上品，稀有 |
| 天 | ×8.0 | 极品，顶级 |

### 5.1 功法加成（主修功法主要提升攻击/生命/寿元）

```
功法生命加成 = 品阶基数(黄20) × 品阶倍率 × (适用境界序号)
功法攻击加成 = 品阶基数(黄6)  × 品阶倍率 × (适用境界序号)
功法寿元加成 = 品阶基数(黄10) × 品阶倍率 × (适用境界序号)
```

### 5.2 法宝加成（法宝主要提升攻击/防御/速度）

```
法宝攻击加成 = 品阶基数(黄8) × 品阶倍率 × (适用境界序号)
法宝防御加成 = 品阶基数(黄6) × 品阶倍率 × (适用境界序号)
法宝速度加成 = 品阶基数(黄4) × 品阶倍率 × (适用境界序号)
```

## 十一、数值平衡说明

1. **成长加速**：境界序号作为乘数，保证高境界角色对低境界形成碾压，符合修仙设定。
2. **品阶拉开差距**：天地玄黄 ×8/×4/×2/×1，同境界下天阶功法显著强于黄阶。
3. **体质差异**：稀有体质（九幽玄阴体）提供更高上限，增加角色多样性。
4. **灵根倾向**：不同灵根决定攻防速倾向，鼓励差异化流派。
5. **寿元独立**：寿元只由境界上限 + 体质/功法/法宝加成决定，不随小境界层数线性成长（每层 = 上限/9，最终恰好等于上限）。

## 十三、修炼突破体系（经济 + 灵气 + 寿元）

以「灵石」为主货币、「灵气」为修炼资源，二者与「寿元（天数）」共同构成完整的修仙成长闭环：

```
攒灵石 + 攒灵气 → 购功法/法宝 → 突破境界（消耗灵石+灵气+天数）
                                          ↑
       打坐(+灵气) / 除妖(+灵气+灵石) / 挖矿(+灵石) —— 均消耗天数，与寿元挂钩
```

### 13.1 初始资源

- 新用户注册初始 **0 灵石**（`t_user.spirit_stone`）+ **0 灵气**（`t_user.spirit_qi`）+ **0 已耗天数**（`t_user.age_used`）。
- 灵石、灵气均靠打坐/除妖/挖矿/月俸逐步积累，突破境界、购买功法法宝时消耗。

### 13.2 物品定价公式

```
价格 = 品阶价格池 × 境界系数 × 类别价格系数
```

- **品阶价格池**：黄 100 / 玄 300 / 地 800 / 天 2000
- **境界系数**（与数值系统一致）：练气×1 → 筑基×1.5 → 金丹×2.5 → 元婴×4 → 化神×6 → 炼虚×8 → 合体×10 → 大乘×12 → 渡劫×15
- **类别价格系数**：
  - 功法：主修功法×1.0，神通×1.2，炼丹/符箓/阵法/傀儡/炼器×0.8，法术/秘术×0.6
  - 法宝：飞剑/攻伐/护身×1.0，遁法×0.9，奇物×1.1，储物×0.5

### 13.3 突破费用

每提升一个小境界，同时消耗 **灵石 + 灵气 + 闭关天数**。费用随「境界」与「层数」双重递增：

```
实际费用 = 境界基础费 × (1 + 0.15 × (目标层小层数 - 1))
```

- **境界基础费**：由目标层所在大境界决定（跨大境界大幅跳升）；
- **层数因子**：同一大境界内，越接近本境界圆满（第 9 层），费用越高（末层约首层 2.2 倍），
  实现「每一层突破都比上一层更贵」的平滑曲线；
- 本境界末层费用仍低于下一大境界首层，整体曲线无缝衔接。

各境界「突破到下一层」的基础费：

| 大境界 | 灵石/层(基础) | 灵气/层(基础) | 闭关天数/层(基础) |
|:---:|:---:|:---:|:---:|
| 练气期 | 20 | 10 | 1 |
| 筑基期 | 50 | 25 | 2 |
| 金丹期 | 120 | 60 | 3 |
| 元婴期 | 300 | 150 | 5 |
| 化神期 | 800 | 400 | 8 |
| 炼虚期 | 2000 | 1000 | 13 |
| 合体期 | 5000 | 2500 | 21 |
| 大乘期 | 12000 | 6000 | 34 |
| 渡劫期 | 30000 | 15000 | 55 |

> 例：练气期突破费用随层数递增为 20 / 23 / 26 / 29 / 32 / 35 / 38 / 41 / 44 灵石；
> 第 9 层（44）仍低于筑基期首层（50），跨境界再跳升。

突破规则：
- 灵石不足 / 灵气不足 → 返回 400 拒绝。
- 寿元不足（闭关天数导致坐化）→ 返回 400 拒绝。
- 突破成功后 `total_level +1`，扣除对应灵石、灵气，并累加 `age_used` 闭关天数。

### 13.4 购买规则

- `POST /api/economy/buy/manual/{id}`：扣除灵石，将该功法设为当前主修（装备到 `initial_gongfa`）。
- `POST /api/economy/buy/treasure/{id}`：扣除灵石，将该法宝设为当前法宝（装备到 `initial_treasure`）。
- 灵石不足返回 400；物品不存在返回 404；未登录返回 401。

### 13.5 资源获取（打坐 / 除妖 / 挖矿）

三种途径均 **消耗天数**（与寿元挂钩），带冷却时间：

| 途径 | 奖励 | 天数消耗 | 冷却 |
|:---:|:---:|:---:|:---:|
| 打坐修炼 | +20 灵气 | 1 天 | 60 秒 |
| 斩妖除魔 | +30 灵气 +100 灵石 | 3 天 | 5 分钟 |
| 深入矿脉 | +150 灵石 | 5 天 | 5 分钟 |

- `POST /api/economy/earn/meditate`：打坐修炼（+灵气）
- `POST /api/economy/earn/hunt`：斩妖除魔（+灵气 +灵石）
- `POST /api/economy/earn/mine`：深入矿脉（+灵石）
- 冷却未到 → 返回 400 并附带 `cooldown`（剩余秒数）；冷却状态存于 `t_user.last_meditate_at` / `last_hunt_at` / `last_mine_at`。
- **寿元耗尽**（消耗天数后 `age_used` 超过寿元上限折算天数）→ 返回 400 拒绝该次操作。

### 13.6 寿元机制

- **已耗天数**：字段 `t_user.age_used`，每次打坐/除妖/挖矿/突破都会累加对应天数。
- **剩余寿元（年）**：
  ```
  剩余寿元 = 境界寿元上限 + 体质寿元加成 - floor(age_used / 365)
  ```
  - 境界寿元上限见 `RealmEnum.lifespan`（练气 100 → 渡劫 30000 年）。
  - 体质寿元加成见 `PhysiqueEnum.lifespan`（如九幽玄阴体 +80 年）。
  - 结果向下取整，最低 0。
- **坐化判定**：任何消耗天数的操作，若执行后 `age_used > 剩余寿元 × 365`，视为寿元耗尽，操作被拒绝。
- 剩余寿元与已耗天数在 `GET /api/stats/me` 中返回（`remainingLifespan` / `ageUsed`），前端修为页实时展示。
- **五维「寿元」同步**：五维属性卡片的「寿元」直接展示「剩余寿元」（`total.lifespan = remainingLifespan`），
  与顶部「剩余寿元」完全一致，随消耗实时减少。

### 13.7 资源获取冷却持久化

- 打坐/除妖/挖矿的冷却状态存于 `t_user.last_meditate_at` / `last_hunt_at` / `last_mine_at`。
- `GET /api/stats/me` 额外返回 `meditateCd` / `huntCd` / `mineCd`（剩余秒数），
  前端刷新页面后据此恢复倒计时，冷却不会因刷新而丢失。

### 13.8 门派系统

- **门派数据**：`t_sect` 表（12 个修仙门派/势力，含阵营、地域、镇派绝学、代表人物）。
- **加入**：`POST /api/sects/join/{id}`，写入 `t_user.sect`（门派名）；散修无需加入。
- **弟子级别**（按修为境界自动判定，随突破自动升级）：
  | 修为境界 | 弟子级别 | 月俸灵石 | 月俸灵气 |
  |:---:|:---:|:---:|:---:|
  | 练气 / 筑基 | 外门弟子 | 100 | 50 |
  | 金丹 / 元婴 | 内门弟子 | 500 | 200 |
  | 化神及以上 | 真传弟子 | 2000 | 800 |
- **月俸**：`POST /api/sects/salary` 领取，30 天冷却（`t_user.last_salary_at`），发放灵石+灵气。
- **三大场所**：门派主页展示「藏宝阁 / 丹房 / 练功房」三处宗门重地（各有说明）。
- 相关接口：`GET /api/sects/my`（查询加入状态）、`POST /api/sects/leave`（退出门派）。
